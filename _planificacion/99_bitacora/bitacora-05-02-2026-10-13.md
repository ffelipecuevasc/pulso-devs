## Resumen

Se hizo el inventario de orígenes de la portada y de la 404, medido sobre `dist/` (`pnpm build`) y sobre las respuestas reales de producción pedidas con `Accept: text/html`. **Todo es del propio dominio, salvo el script de Cloudflare Web Analytics** (`https://static.cloudflareinsights.com`), que Cloudflare inyecta en el borde. El sitio **no necesita `'unsafe-inline'`** en `script-src` ni en `style-src`: usa 4 scripts en línea y 2 bloques `<style>` en línea, todos con hash, y ningún atributo `style=""` ni manejador `on*`.

El soporte nativo de Astro 7.3.8 (`security.csp`) existe y se probó, pero **no sirve tal cual**: entrega la política en una etiqueta `<meta>` (sin `frame-ancestors` ni modo solo informe), no incluye el hash del script del tema (`is:inline`) y agrega hashes de código que el sitio no usa. Se recomienda en cambio **escribir la política en `public/_headers` con los hashes fijos y hacer fallar `pnpm build` si no coinciden con `dist/`** (una integración de unas 80 líneas, sin dependencias, probada en una copia fuera del repositorio).

El texto de la política se probó con Chrome 155 por protocolo, en solo informe y aplicada, con el HTML real de producción servido desde una máquina local: **0 violaciones** en portada y 404, en claro y oscuro, con menú móvil, cambio de tema y recarga. Eso **no** reemplaza la prueba en producción de la fase B (ver «No se pudo medir o verificar»).

## Cómo generar y mantener los hashes (paso 3)

**Lo que se probó en una copia del proyecto** (en la carpeta temporal de la sesión, con `node_modules` enlazado; el repositorio no se tocó): se activó `security: { csp: true }` en `astro.config.mjs` y se compiló.

- La etiqueta emitida es `<meta http-equiv="content-security-policy" content="font-src 'self'; script-src 'self' 'sha256-…' ×8; style-src 'self' 'sha256-…' ×3;">`, **idéntica en la portada y en la 404**.
- **No incluye el hash del script del tema** (581 B, `is:inline`): sin él, el script del `<head>` quedaría bloqueado. Los tres módulos en línea sí.
- Agrega **5 hashes de script y 1 de estilo** que no corresponden a nada del HTML publicado. Por lectura del código de Astro (`node_modules/astro/dist/core/csp/common.js`), los 5 hashes de script salen de las directivas de cliente que Astro trae por defecto y el de estilo, de las hojas de estilo del cliente (**leído, no comprobado hash por hash**; el hash de estilo no coincide con el SHA-256 del CSS publicado, no averigüé por qué). Ensanchan la política sin que el sitio los use.
- Pone `'self'` en `script-src` aunque no haya scripts externos del sitio.
- Por ser `<meta>`: no admite `frame-ancestors` ni Report-Only (MDN), así que **no sirve para el primer despliegue en solo informe** y habría que mantener `_headers` de todos modos.

### Comparación de formas de mantener los hashes

Todas evitan `'unsafe-inline'` en `script-src`.

**D · Sacar los scripts a archivos externos** (`vite.build.assetsInlineLimit: 0`, `script-src 'self'`) se descartó sin implementar: sumaría tres peticiones a una primera vista de 9, en un sitio con Lighthouse 99, y el script del tema (en `<head>`) tendría que seguir en línea para no parpadear.

### La integración recomendada, probada en la copia (propuesta; no está en el repositorio)

Archivo nuevo `src/integraciones/verificarCsp.js` y su registro en `astro.config.mjs` (`import verificarCsp from './src/integraciones/verificarCsp.js'` y `verificarCsp()` en `integrations`, junto a `bloquearPendientes()`). Solo lee `dist/`; no escribe nada.

```js
import { readFile } from 'node:fs/promises';
import { createHash } from 'node:crypto';
import { fileURLToPath } from 'node:url';
import path from 'node:path';

const PAGINAS = ['index.html', '404.html'];
const CABECERAS = ['content-security-policy', 'content-security-policy-report-only'];

/** Hash `'sha256-…'` (en base64) del contenido exacto de un bloque en línea. */
const hash = (contenido) =>
  `'sha256-${createHash('sha256').update(contenido, 'utf8').digest('base64')}'`;

/** Hashes de los `<script>` y `<style>` en línea de un HTML (el JSON-LD no se ejecuta y no cuenta). */
function hashesEnLinea(html) {
  const scripts = [...html.matchAll(/<script\b([^>]*)>([\s\S]*?)<\/script>/gi)]
    .filter(([, atributos]) => !/\bsrc=/i.test(atributos) && !/application\/ld\+json/i.test(atributos))
    .map(([, , contenido]) => hash(contenido));
  const estilos = [...html.matchAll(/<style\b[^>]*>([\s\S]*?)<\/style>/gi)].map(([, c]) => hash(c));
  return { scripts, estilos };
}

/** Hashes que declara la política de `_headers` en una directiva (`script-src` o `style-src`). */
function hashesDeclarados(politica, directiva) {
  const parte = politica.split(';').find((d) => d.trim().startsWith(`${directiva} `)) ?? '';
  return parte.match(/'sha256-[^']+'/g) ?? [];
}

/**
 * Integración de Astro que hace fallar `pnpm build` si los hashes de la política
 * `Content-Security-Policy` de `_headers` no coinciden con los scripts y estilos en línea de
 * `dist/`. Evita desplegar un hash desactualizado.
 *
 * @returns {import('astro').AstroIntegration}
 */
export default function verificarCsp() {
  return {
    name: 'verificar-csp',
    hooks: {
      'astro:build:done': async ({ dir }) => {
        const carpeta = fileURLToPath(dir);
        const encabezados = await readFile(path.join(carpeta, '_headers'), 'utf8');
        const politicas = encabezados
          .split(/\r?\n/)
          .map((linea) => linea.trim())
          .filter((linea) => CABECERAS.some((c) => linea.toLowerCase().startsWith(`${c}:`)))
          .map((linea) => linea.slice(linea.indexOf(':') + 1));
        const completas = politicas.filter((p) => p.includes('script-src'));
        if (completas.length === 0) return; // sin política completa todavía

        const reales = { scripts: new Set(), estilos: new Set() };
        for (const pagina of PAGINAS) {
          const html = await readFile(path.join(carpeta, pagina), 'utf8');
          const { scripts, estilos } = hashesEnLinea(html);
          scripts.forEach((h) => reales.scripts.add(h));
          estilos.forEach((h) => reales.estilos.add(h));
        }

        const problemas = [];
        for (const politica of completas) {
          for (const [directiva, conjunto] of [
            ['script-src', reales.scripts],
            ['style-src', reales.estilos],
          ]) {
            const declarados = new Set(hashesDeclarados(politica, directiva));
            for (const h of conjunto)
              if (!declarados.has(h)) problemas.push(`falta en ${directiva}: ${h}`);
            for (const h of declarados)
              if (!conjunto.has(h)) problemas.push(`sobra en ${directiva} (ya no existe en dist/): ${h}`);
          }
        }
        if (problemas.length > 0) {
          throw new Error(
            `La política Content-Security-Policy de public/_headers no coincide con dist/:\n` +
              [...new Set(problemas)].map((p) => `  - ${p}`).join('\n') +
              `\nActualiza los hashes en public/_headers y vuelve a compilar.`,
          );
        }
        console.log(
          `[verificar-csp] OK: ${reales.scripts.size} scripts y ${reales.estilos.size} estilos en línea coinciden con public/_headers.`,
        );
      },
    },
  };
}
```

**Pruebas en la copia** (con la política en solo informe pegada en `public/_headers`):

| Caso | Resultado |
| :--- | :-------- |
| Sin cambios | `[verificar-csp] OK: 4 scripts y 2 estilos en línea coinciden con public/_headers.` y el build termina bien |
| Se agrega un comentario al final de la línea `setAttribute('data-theme', …)` del script del tema | **El build falla** (salida distinta de cero): «falta en script-src: 'sha256-0E3dnyz…' · sobra en script-src (ya no existe en dist/): 'sha256-h/2vF1a…'» |
| Se agregan dos líneas a `src/scripts/pulso-logo.js` | **El build falla**: «falta 'sha256-ixe37Ae…' · sobra 'sha256-4n2jxXV…'» |
| Se deshacen los cambios | El build vuelve a pasar |

Limitaciones: solo compara scripts y estilos **en línea**; un script **externo** nuevo no se detecta en el build (la CSP lo bloquearía y se vería en la consola). Una política sin `script-src` (como la actual, solo `frame-ancestors`) se ignora, por eso se puede agregar antes que la política completa. El código de la integración tiene que pasar `pnpm format` y `pnpm check` cuando se implemente.

## Texto propuesto de la política (paso 4)

Un solo texto para toda la regla `/*`, que sirve a la portada y a la 404 (la 404 usa 3 de los 4 hashes de script; el cuarto, el de `pulso-logo.js`, solo lo usa la portada). Longitud de la política: **524 caracteres**; la línea más larga de `_headers` queda en **563** (límite: 2.000), con 2 reglas (límite: 100).

### Política completa (la misma en las dos versiones)

```text
default-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; script-src 'sha256-h/2vF1aGIpynrKup+U0y4UdjUccVza7jUMeVEMLLbl0=' 'sha256-851aDHlfSJm2ydIXYm/xjb9zqg+shmbIx5mxnUhebE0=' 'sha256-HKhVVZuR4nQlaNFrH3ZgfmRaAdVXfgd/JHMp0yls/Ug=' 'sha256-4n2jxXVJdkQWX3vxghpJGru3u8tRbr4YjeB/aLeD/l8=' https://static.cloudflareinsights.com; style-src 'self' 'sha256-efEqBBTmDx23cBukE2XkM2PKDzUd+1rZ8FL0uQQQgsM=' 'sha256-yY2AedDjJ6Wcw74TL9jTKsyjFy0AkGKpgxGoGssDOdQ='; img-src 'self'; font-src 'self'; connect-src 'self'
```

| Directiva | Valor | Por qué | Respaldo del inventario |
| :-------- | :---- | :------ | :---------------------- |
| `default-src` | `'none'` | Todo lo que no se nombra abajo queda prohibido (frames, medios, objetos, workers, manifest, etc.) | El inventario no encontró ninguno de esos usos |
| `base-uri` | `'none'` | Nadie puede fijar un `<base>` | 0 `<base>` en las dos páginas |
| `form-action` | `'none'` | El sitio no envía formularios (RDA-006) | 0 `<form>` |
| `frame-ancestors` | `'none'` | Nadie puede incrustar el sitio; es lo que ya aplica hoy | Cabecera actual medida en producción |
| `script-src` | los 4 hashes y `https://static.cloudflareinsights.com` | Permite exactamente los 4 scripts en línea del sitio y el script de Web Analytics; **sin `'unsafe-inline'`, sin `'unsafe-eval'` y sin `'self'`** (no hay scripts externos propios) | Tabla de scripts; etiqueta inyectada de Cloudflare con `src` en ese host (un origen sin ruta cubre la ruta con el hash de versión) |
| `style-src` | `'self'` y 2 hashes | La hoja de estilos del propio dominio y los dos `@font-face` en línea de Astro Fonts; **sin `'unsafe-inline'`** | Tabla de estilos; 0 atributos `style=""` |
| `img-src` | `'self'` | AVIF, WebP, PNG y favicons del propio dominio | 0 URI `data:`; todas las imágenes en `/_astro/` o en la raíz |
| `font-src` | `'self'` | Los dos `.woff2` del propio dominio | Tabla de fuentes |
| `connect-src` | `'self'` | El beacon envía a `/cdn-cgi/rum` del propio origen | Medido en producción en 05-01 (204) y en el Chrome local |

**Qué NO se permite:** scripts en línea sin hash (incluido cualquier script nuevo que se agregue al HTML), `eval`, manejadores `onclick=` y similares, URL `javascript:`, scripts externos salvo `static.cloudflareinsights.com`, hojas de estilo en línea sin hash y atributos `style=""` (el CSS aplicado desde JavaScript con `element.style` queda fuera de este bloqueo), imágenes, fuentes o conexiones a otros dominios (incluido `cloudflareinsights.com` como destino de `connect-src`), `data:` y `blob:`, marcos (`<iframe>`), formularios, `<base>`, plugins (`<object>`, `<embed>`), medios, workers y manifiestos.

### (a) Primer despliegue: solo informe (`public/_headers`)

```text
/*
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  X-Frame-Options: DENY
  Content-Security-Policy: frame-ancestors 'none'
  Content-Security-Policy-Report-Only: <la política completa de arriba, en una sola línea>

/_astro/*
  Cache-Control: public, max-age=31536000, immutable
```

- **Sin endpoint de reportes** (ni `report-to` ni `report-uri`): el navegador solo anota las violaciones en la consola. En el Chrome 155 local las anotó como `security/info` (medido).
- La cabecera `Content-Security-Policy: frame-ancestors 'none'` **se conserva sin cambios** y sigue aplicada. Son **dos cabeceras distintas** (nombres distintos), así que Cloudflare no las une con coma; **la regla de unión solo afecta a una misma cabecera repetida**.
- **`frame-ancestors` en solo informe: se evalúa (no se ignora).** Medido en Chrome 155: una página de otro origen que incrusta la portada con solo la cabecera Report-Only recibe «Framing … violates the following report-only Content Security Policy directive: "frame-ancestors 'none'". The violation has been logged, but no further action has been taken.» (la página se carga igual). Coincide con MDN, que solo exceptúa `sandbox`. Por eso repetir `frame-ancestors 'none'` en la versión de solo informe es inofensivo, y es necesario mantener la cabecera aplicada aparte para que siga protegiendo durante la prueba.
- **Ensayo en el despliegue 1:** `connect-src` lleva **solo `'self'`**. Permitir también `https://cloudflareinsights.com` «para no ver ruido» **taparía la respuesta**: si el beacon enviara a ese origen, no habría violación y no sabríamos cuál se usa. Con solo `'self'`: si el beacon va a `/cdn-cgi/rum`, no aparece nada (esperado, medido en 05-01 en producción); si va a `cloudflareinsights.com`, aparece una violación `connect-src` que **nombra el origen exacto**, y en el despliegue 2 se agrega solo ese. La prueba de ocultar la página (W2 y W3 de la evidencia) es la que lo decide. **A confirmar en producción.**

### (b) Segundo despliegue: política aplicada (`public/_headers`)

```text
/*

  Referrer-Policy: strict-origin-when-cross-origin
  X-Frame-Options: DENY
  Content-Security-Policy: <la política completa de arriba, en una sola línea>
```

La política completa ya incluye `frame-ancestors 'none'`, así que la línea actual se **reemplaza** (no se suma una segunda `Content-Security-Policy`, que Cloudflare uniría con coma). `X-Frame-Options: DENY` se mantiene.
